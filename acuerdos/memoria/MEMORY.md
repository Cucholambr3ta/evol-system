# Riesgos activos

> Atomo de MEMORY. Riesgos vigentes y mitigaciones.

- **[MITIGADO] `docs/evol-dd_Integration_Guide.md` sin rebrand:** Se reescribió la guía por completo aplicando el estricto `DOC_STANDARD`, eliminando el legacy naming e inyectando la nueva filosofía.
- **[MITIGADO] memory/ no existia en bootstrap:** La carpeta `memory/` no era creada por `evol-init.sh`, causando que herramientas como `evol-shield.py` no pudieran verificar sus permisos. Fix aplicado en v0.5.0: `evol-init.sh` la crea con permisos `750`.
- **[MITIGADO] Memoria no se actualizaba en releases:** El flujo `release-close` no existia, dejando `acuerdos/memoria/` desactualizado tras cada release. Fix aplicado en v0.5.0: nuevo subcomando `evol-gitflow.sh release-close --version=X.Y.Z`.
- **[MITIGADO] Sidecars de disciplinas y documentación pueden driftar:** Se automatizó por completo la sincronización de sidecars y la regeneración de catálogos en `cmd_sprint_close` y `cmd_release_close` dentro de `evol-gitflow.sh` (sprint anterior y fusionado en `develop`).
- **Commits sin firma GPG en main:** GitHub reporta violaciones de firma en los commits del release v0.5.0. Actualmente bypaseados por reglas del repositorio, pero requieren configurar GPG signing localmente para cumplir la politica de rama protegida en futuros releases.
- **`evol update check` reporta PyPI stale:** El script usa `info.version` del JSON de PyPI (campo "latest stable"), que puede quedar en versión anterior si PyPI no actualiza el campo inmediatamente después de `twine upload`. Workaround: `curl -s https://pypi.org/pypi/evol-dd/json | python3 -c "import sys,json; print(max(json.load(sys.stdin)['releases']))"` para verificar versión real publicada.
- **WORKING-CONTEXT.md desactualizado (skills count + version):** Dice "9 skills" y "v0.6.3" pero CATALOG.json tiene 82 skills (70 core + 12 extra), VERSION=0.6.0, pyproject.toml=0.6.3. Necesita actualización completa en próximo sprint-close o release-close.
- **[MITIGADO] EDMS no implementado:** Completado v0.6.1: 6 fases + expanded indexing, ChromaDB + LadybugDB activos en `.venv/`, 52 tests passing. Grafo con 261+ entries, 105+ items bootstrapped, 63+ drawers. Fallback stdlib permanece disponible para proyectos sin dependencias opcionales.
- **[MITIGADO] Dependencia en ChromaDB/LadybugDB:** Ambas son dependencias opcionales. `pip install evol-dd` funciona sin ellas. Fallback BM25 stdlib con búsqueda local por keywords + NetworkX como graph fallback. Auto-detect venv en `evol_memory_store.py` maneja instalación transparente.
- **[NUEVO] LadybugDB como dependencia nueva:** LadybugDB (v0.17.1) es un paquete relativamente nuevo. Cypher queries con dict parameters requieren formato específico (`{name: $name}` no `$name`). Properties deben ser base64-encoded para evitar interpretación como Cypher map literals. Mitigación: tests exhaustivos (11 nuevos), fallback a NetworkX si LadybugDB no disponible.
- **[NUEVO] Real-time monitoring adds complexity:** 4 nuevos módulos stdlib (traces, sse_server, state_machine, loop_detector) + integración en evol_memory_store.py y hooks. El SSE server corre como daemon separado. Mitigación: todo es stdlib (0 deps), emit calls fallan silenciosamente si evol_traces no está disponible, hooks usan `|| true` para no bloquear.
- **[NUEVO] EDMS v2.0 adds 18 components (~4600 lines):** 4 fases con 18 componentes nuevos en `scripts/evol_memory_v2/`. Complejidad de维护 significativa. Mitigación: 137 tests covering all components, 0 external dependencies, backward-compatible via MemoryV2 compat layer, `EVOL_MEMORY_V2_ENABLED` env var para activar/desactivar.
- **[NUEVO] Migration v1→v2 risk:** Migración de datos existentes a nuevo formato puede perder datos. Mitigación: snapshot antes de migrar, dry-run mode, verificación post-migración con checksums, rollback via snapshot restoration.
- **[NUEVO] API server adds runtime complexity:** `api.py` expone HTTP endpoints para la UI web. Necesaria porque la UI (browser) no puede ejecutar subprocess de Python directamente. Mitigación: stdlib `http.server` (0 deps), lazy start (solo corre cuando UI la pide), health check endpoint, auth_token opcional, CORS configurable. La API es **opcional** — si no hay UI, no corre.
- **[NUEVO] VERSION drift persistente:** `pyproject.toml` dice 0.6.3, `VERSION` y `src/evol_cli/VERSION` dicen 0.6.0. La decisión de "Drift de VERSION corregido" dice que ambos están sincronizados a 0.6.0, pero pyproject.toml fue actualizado a 0.6.3 sin sincronizar los otros. Mitigación: sincronizar todos los archivos VERSION en próximo sprint-close o release-close.
- **[NUEVO] npm installation adds Node.js dependency:** El método npm (`package.json` + wrappers en `bin/`) requiere Node.js como runtime dependency. Usuarios sin Node.js no pueden usar `npm install -g evol-dd`. Mitigación: npm es complementario a pip/install.sh, no el primary. `install.sh` detecta y prefiere pipx/pip sobre npm.
- **[NUEVO] Local-only skills not in package:** `revision-release`, `update-context`, `update-memory` viven en `~/.agents/skills/` pero no se distribuyen en PyPI/npm. Si el usuario reinstala el sistema o cambia de máquina, estas skills se pierden. Mitigación: `/update-context` sincroniza contexto entre IDEs, pero las skills mismas requieren reinstalación manual o backup de `~/.agents/skills/`.

- **[NUEVO] TUI requiere deps opcionales no garantizadas (textual/netext/networkx):** `scripts/evol_tui/` depende de `textual>=0.80`, `netext>=0.5.0`, `networkx>=3.0`, `textual-canvas`. Si no instaladas, la app no arranca. Mitigación: graphs tienen fallback ASCII automático (try/except ImportError + AttributeError), pero el `App` mismo requiere `textual`. Smoke test corrió en venv temporal — falta declarar como extra opcional (`tui`) en `pyproject.toml` antes de distribuir.
- **[NUEVO] ThreeJS bundle size 351 KB gz:** El chunk de ThreeJS + @react-three/fiber + @react-three/drei + @react-three/postprocessing es el más grande del bundle PWA (1,234 KB raw, 351 KB gz). Mitigación: code splitting aplicado (chunk separado `three`), lazy loading de pantallas que no usan 3D, y service worker cache-first para assets estáticos.
- **[NUEVO] EDMS Web PWA depende de servidores externos:** La app React se comunica con SSE server (puerto 8765) y Memory v2 API (puerto 8766). Si los servidores no están corriendo, la app muestra datos estáticos de fallback. Mitigación: TanStack Query con stale-while-revalidate, SSE reconexión automática, health check endpoint.
- **[NUEVO] update-memory y update-context ahora en paquete distribuible:** Ambas skills movidas de local-only a skills del paquete. Si el usuario tiene customizaciones locales, serán sobrescritas al actualizar evol-dd. Mitigación: las versiones del paquete son la SSoT; customizaciones deben hacerse en el paquete, no en ~/.agents/skills/.
- **[NUEVO] 21st.dev MCP server dependencia externa:** El MCP server `@21st-dev/magic` depende del servicio 21st.dev y una API key válida. Si el servicio cae o la API key expira, las herramientas de búsqueda de inspiración y generación de componentes no funcionan. Mitigación: la skill ui-ux-pro-max funciona independientemente con sus scripts Python locales; el MCP es complementario.
